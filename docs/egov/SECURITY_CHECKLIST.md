# Чек-лист информационной безопасности — по пяти видам испытаний ГТС

> **English summary.** The five test types of the State Technical Service (source-code analysis,
> security-function tests, load testing, network survey, security-process survey) are mapped to
> the evidence that already exists in this repository and to what is missing. Existing evidence
> includes the architecture tests, the audit-chain `verify` command, fail-closed key handling,
> pinned dependencies and the self-hosted, hash-checked browser runtime. The gaps are stated
> plainly, with their `docs/LEGAL_ASSESSMENT.md` §6 ids (M1–M11, S1–S7) where one applies. The
> largest gaps: no Kazakhstan hosting, no load test, no network diagram for a production
> contour, no SBOM or static-analysis run, no MFA/SSO for analysts, no written security-process
> documents (ТД ИБ, incident response with the 1-working-day breach notice, a named responsible
> person) and no SOC contract.

_Состояние на 2026-10-08, ветка `sanzh-ts` @ `54a6f0b`; строки, закрытые ADR D66, обновлены
2026-10-09 (маскировка чисел словами, имён и IBAN; SBOM; pip-audit, npm audit, bandit; срок
хранения журнала аудита)._

  устранение замечаний даётся 60 р.д.; два бесплатных повторных испытания проводятся в течение
  20 р.д. [A]. Источники: https://zakon.uchet.kz/rus/docs/V1900018795 , https://synaq.sts.kz/ .
