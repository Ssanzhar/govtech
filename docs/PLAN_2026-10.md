## 2. The honest numbers

The training data shares its generator with test / ood / authored, so those splits flatter us.
**The headline is `shift_local`** (a different model family, with no access to our data; ADR D65).

| | False-alarm rate (FPR) | Recall |
|---|---|---|
| v1 on `shift_local` | 0.062 [0.017, 0.152] (4/64)¹ | 0.548 [0.417, 0.675] |
| v1 on `shift_local`, by language | kk 0.080 · ru 0.000 · en 0.133 | kk 0.458 · ru 0.625 · en 0.571 |
| v1 live meter on `shift_local` | false alert on 8/64 legit calls | alert on 0.694 of scams |
| v1 on `court_quotes` (real RU phrases, positives only) | — | 29/47 scored risky; **a keyword trigger fires on only 1/47** |

¹ 3/64 in the D63 run (device embeddings instead of the server proxy); both are on record.

**What we learned from v2 (D63 phase 2).** The retrain on the new taxonomy + Claude data ranks
calls better (validation ROC-AUC 0.956 vs 0.872) and on held-out data gave:
- `shift_local` recall 0.548 → **0.661** at the same FPR (3/64); `court_quotes` 29 → **41/47**;
- but test FPR 0 → 2/60 and ood 0 → 3/74, and legit-sounding scam recall 0.862 → 0.716.

Of the 5 new false alarms, **2 were ordinary family money requests by Kaspi**: the new
"relative" and "payment redirect" heads learned "a relative asking for money" as a scam. So
v2 is not shipped. The fix is more legitimate family/bank calls in training (v2.1).

**What the real phrases tell us.** Real scammers talk about accidents, relatives and
«декларирование», not «код из СМС». The keyword triggers almost never fire on real phrasing,
so recall has to come from meaning (the embedding heads), which is what taxonomy v2 trains.

## 3. The strategy, in five rules

1. **False alarms first.** Nothing ships if FPR rises on test / authored / ood / ASR-styled data
   or the browser gate, unless an ADR records the exception and the user approves it.
2. **The judge must be independent.** Claude now writes training data, so Claude-written test
   sets (`shift`, now `shift_v1`) only count as validation. Judges: `shift_local` /
   `shift_local_2` (local Kazakh model), `court_quotes` (real phrases), and later `real_asr`
   (our recordings).
3. **Pre-register, then look once.** Every setting is chosen on validation and committed with
   the weights' sha256 *before* any held-out split runs. The ship criteria are written down
   first. If they fail, we stop: no re-tuning against held-out results.
4. **Meaning over keywords.** New scam types are learned from meaning only. The keyword
   lexicon changes only with paired training data, and never from held-out rows.
5. **Privacy by architecture.** No audio leaves the device, nothing is published from
   `data/raw/` or the held-outs, and `tests/test_architecture.py` stays green.
