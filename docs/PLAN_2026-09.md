## 1. Evidence gathered on 2026-09-11 (what the plan rests on)

**Privacy / data flow (code audit)**
- Mic mode streams raw PCM16 to the server over WebSocket (`site/live_mic.js:48`,
  `src/qorgan/api_live_ws.py`); replay mode POSTs every utterance (`site/live.js:236`); live
  transcripts sit in server memory, LRU, no TTL (`live/session_store.py`).
- Consented reports append **raw phone number + raw transcript** (`live/summary.py:128`); L2
  intake neither scrubs nor hashes (`analytics/intake.py`); `Incident.phone_number` is raw;
  the analyst API returns full transcripts (`api_admin.py:280`). `data/scrub.py` is used only
  by `build_corpus` / `incident_seed`. Nothing logs transcripts; `/api/analyze` retains nothing.
- `site/index.html` hero/how/evidence copy describes a *voice anti-spoofing* detector — wrong.

**Classifier portability (code audit + measurements)**
- Risk head = `CalibratedClassifierCV` (3 × LogisticRegression over 774 dims + Platt);
  tactic head = 15 × LogisticRegression over 768 dims → a ~60 KB JSON. Cue matching is
  lowercase-substring; reassurance is a lookbehind-free regex; explainer/advice/meter/windowing
  are pure logic. All portable to JS 1:1.
- **Model choice measured, not assumed.** Heads retrained on `multilingual-e5-small`
  (`models/linear_e5small/`, same harness, threshold 0.55):

  | split | e5-base (shipped) FPR / recall | e5-small FPR / recall |
  |---|---|---|
  | test | 0.000 / 0.953 | **0.019** / 0.953 |
  | authored heldout | 0.000 / 1.000 | 0.000 / **0.778** (RU 0.667) |
  | ood | 0.000 / 0.889 | **0.013** / 0.867 |

  Re-tuning the threshold to 0.24 "recovers" recall 0.944 — by tuning on the held-out (the
  circularity the council flagged) — and the margins overlap (lowest scam 0.155 < highest
  legit 0.205). Capacity gap, not a threshold problem. **Decision: `multilingual-e5-base`
  stays; the browser artifact is `Xenova/multilingual-e5-base` int8 = 278 MB.**
- **Quantization drift is negligible:** int8 ONNX vs fp32 cosine mean 0.999 / min 0.9975 on
  200 real texts (measured on e5-small; verify on base in B3).
- **Latency is not the constraint:** native int8 = 7 ms per transcript, 3 ms per utterance
  (laptop CPU). Even 10× slower in WASM and 4× for base, a live turn stays < 300 ms.
- Per-tactic F1 on the authored set is poor for `impersonation_telecom_delivery` (0.00),
  `urgency` (0.17), `verification_ploy` (0.29) → the synthetic corpus is thin there.

**Evaluation honesty**
- `real_heldout` (42) is **author-written**: 18 scam / 24 legit. ≥5 of the 24 negatives are
  named in code/tests/docs as inspected FPs or sentinels (`real_neg_bank_fraud_alert_ru`,
  `real_neg_telecom_tariff_ru`, `real_neg_bank_card_ready_ru`,
  `real_neg_telecom_tariff_notice_mixed`, `real_neg_bank_card_delivery_kk`).
- 0 FP on n=24 → 95 % one-sided Clopper–Pearson upper bound on FPR = **0.117**; recall 18/18
  → lower bound **0.847**; streaming false-latch 4/24 → 95 % CI **[0.05, 0.37]**. Bounding
  FPR ≤ 5 % with zero FPs needs **≥ 59** clean negatives (≤ 3 % → 99; ≤ 2 % → 149).
- `eval/metrics.py` has no CI/bootstrap code; `docs/eval_report.md` numbers are pasted.
- Other splits: test 52 neg / 64 pos; ood 75 neg / 45 pos (all synthetic).

**In-browser ASR (external check)**
- `vosk-browser` on npm is **0.0.8 from Dec 2022** — effectively abandoned. Alternatives:
  `msqr1/Vosklet` (Vosk WASM wrapper, active 2026-09); Whisper via transformers.js 4.2 /
  onnxruntime-web 1.29 (both current) with a **bilingual KK+RU whisper-small fine-tune**
  (`KRASR/kazakh-russian-asr-whisper-small-full-ft`) or `akuzdeuov/whisper-base.kk` —
  chunked, not streaming, ~80–250 MB int8. B7 is a 3-way bake-off, not a bet.
- For offline batch transcription of collected calls (A3): `kzmaker/faster-whisper-kk` (CT2)
  drops into `asr/transcribe.py`; `shyngys879/kazakh-whisper-large-v3-turbo` is the quality
  option.

**L2 coupling:** only `api.py` (routers) and `api_live.py` (`report_incident_id`, pure)
import analytics; `hdbscan`/`networkx` are analytics-only; ~129 L2 tests.

## 2. Target architecture (v2)

```
 CITIZEN DEVICE (PWA)                                        SERVER (FastAPI)
 ┌───────────────────────────────────────────────┐          ┌──────────────────────────────┐
 │ paste / replay / (mic → on-device ASR, spike) │          │ /api/analyze   stateless,    │
 │  ─► utterances ─► rolling window              │ explicit │   explicit-request fallback  │
 │  ─► e5-base int8 (ONNX, worker)               │ request  │   for low-end devices +      │
 │  ─► [768 | 5 cue | 1 reassurance] ─► LR+Platt │ (opt-in, │   partner "API signal";      │
 │  ─► meter / explain / advice (JS port)        │ disclosed)│  no retention, no bodies    │
 │ history: IndexedDB, local, deletable          │ ───────► │   in logs                    │
 │                                               │          │ /api/reports   SINGLE INGRESS│
 │ NOTHING ELSE LEAVES THE DEVICE                │ explicit │   citizen + partner; scrub → │
 └───────────────────────────────────────────────┘ submit ► │   HMAC(number) → incident;   │
        ▲ model files (once, cached, self-hosted)            │   receipt; DELETE; retention │
                                                             │ L2 analytics: aggregates;    │
                                                             │   audited drill-down         │
                                                             └──────────────────────────────┘
```

**Invariants (each enforced by a test — C1, G3):**
1. No route accepts audio. (The WebSocket ASR path is removed from the product.)
2. Call content leaves the device only on an explicit user action (submit, or opt-in
   server scoring), and the UI shows exactly what is sent.
3. L2 has a single ingress — consented reports. Live sessions and `/api/analyze` cannot
   write to the analytics store (import-graph test + no-files-written test).
4. Numbers are stored only as salted HMACs (hashed on receipt, raw never persisted);
   transcripts entering L2 are PII-scrubbed.
5. Every report has a receipt, can be deleted, and expires per a configured retention.
6. The partner ingress is not a bulk-transcript feed: structured tactic hits preferred;
   transcripts must be pre-scrubbed and carry a `consent_basis`; per-partner quotas + audit.

**Cheapest compliant alternative, stated honestly:** invariants 1–2 are met by B5+B6 alone
(explicit-submit + remove server ASR, ~2 pd, server still sees transcripts on request).
The on-device port (B1–B4) is the differentiator, not the compliance floor — so B5/B6
ship in W1 regardless of how the port goes.

## 6. Release gates (v2)

- **G1a (mandatory) Honest report:** every table carries CIs; `authored_heldout` shown clean
  vs inspected; `real_heldout_v2` locked and scored once; inspection ledger present.
- **G1b (target) Real-call quality:** on `real_heldout_v2`, FPR 95 % upper bound ≤ 10 % and
  recall lower bound ≥ 0.80, per-language rows present. **If G1b fails**, the release ships
  anyway labelled "research preview" in the UI and README, with the real numbers, and A8's
  real-data training becomes the next cycle's top item. A gate that cannot fail is not a gate;
  a failure that hides the number is worse.
- **G2 Parity:** JS core == Python on ≥ 200 fixtures; browser int8 embeddings agree with
  Python-ONNX (B3 tolerances).
- **G3 Privacy:** architecture tests green; Playwright network audit shows only model files +
  explicit actions; no raw number / unscrubbed transcript on disk; deletion round-trip; partner
  ingress requires `consent_basis` and enforces quotas.
- **G4 Streaming (if A6 done):** false-latch ≤ 2/24 with CI; median turns-to-alert not worse
  by > 1.
- **G5 L2:** single-ingress invariant, hashing, retention, partner API documented, discovery
  notes + ADR D16.
- **G6 Truth:** landing copy, README, STATUS, eval report describe the same product.

## 7. What we need from stakeholders (ranked; brief used on 2026-09-11)

1. **Real call recordings or transcripts — both classes.** Confirmed scam calls **and**
   legitimate calls from the same domains (bank, telecom, delivery, e-gov). The legit half is
   the scarce one and drives FPR. 100–300 labelled calls changes the evaluation; 1,000+
   enables a stronger model. Anonymised/consented; we scrub and hash; on-prem processing
   possible (A8 protocol).
2. **Outcome labels** (which reports were confirmed fraud) + their internal tactic taxonomy.
3. **Kazakh telephone-speech audio** for ASR evaluation.
4. **3–5 interviews** with fraud analysts / hotline operators (C7).
5. **Legal guidance** on using recorded calls (consent, retention) in Kazakhstan — including
   whether the *caller's* speech in a citizen's report needs a separate basis.
6. **Confirmed scam-number lists** (hashed is fine) for organisation linking.
7. **One pilot integration point** willing to receive the risk signal via the partner API.
